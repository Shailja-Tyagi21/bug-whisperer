### how did we fix the memory leak in the worker service?
*26.2s — PASS*

⚠️ [answer_cites_something] answer is substantive but cites no bug IDs at all

> The root cause of the memory leak in the worker service was that the pdf-lib library was creating Document instances per request without disposing of them, causing a gradual increase in memory usage over time. This issue was fixed by wrapping PDF processing in try/finally with explicit doc.unload() to ensure that resources were properly released after use. Additionally, a pod memory alert was added at 80% to prevent the OOM crash, and a streaming approach was implemented for files larger than 10MB to reduce memory usage.

### what caused the database connection pool issue?

> The root cause of the database connection pool issue was that the import job held connections for the full job duration instead of releasing them between chunks. This caused the pool to become exhausted, leading to unrelated requests across the app timing out.
